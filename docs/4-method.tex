\section{Method}
\label{sec:method}

\begin{figure}[t]
    \centering
    \includegraphics[width=\linewidth]{figures/ufuzz.pdf}
    \vspace{-10pt}
    \caption{Overview of \system. A frozen structural index supplies certified
    mutation opportunities and provenance, while an isolated
    reference vault supplies evaluator-only answers and evidence. Each valid

    \label{fig:method}

We develop \system, a fuzzing framework for discovering the memory-use
failures defined in \S\ref{sec:problem}. \system constructs seeds from memory
checkpoints and builds a frozen structural description of each checkpoint
(\S\ref{subsec:seed-init}). It then enumerates applicable mutation
obligations, generates and validates query or memory-state mutants
(\S\ref{subsec:mutation}), and executes valid mutants under a fixed probe
budget (\S\ref{subsec:execution}). Search uses only observable retrieval
behavior and non-oracle structural information. Evaluation references and
failure verdicts remain outside the search loop.

\subsection{Seed and Checkpoint Initialization}
\label{subsec:seed-init}

Let \(H_{1:t}=\langle h_1,\ldots,h_t\rangle\) denote the interaction history
up to time \(t\), and let \(M_t\) denote the resulting memory state. The
history and its stable benchmark source identifiers are retained as provenance
for \(M_t\). A materialization protocol creates an isolated live state from a
persistent logical seed and certifies the resulting state. It may replay a
frozen initialization artifact derived from \(H_{1:t}\) or use a future exact
snapshot-restore mechanism; no snapshot support is currently claimed for the
three backends. Thus, fuzzing does not modify the original task state.

A fuzzing state is denoted \(x=(M_t,q)\), where \(q\) is a query that may use
information in \(M_t\). Its persistent seed identity is an immutable logical
recipe and certificate rather than a live StateHandle, backend object,
vector-store instance, Neo4j group, or replay-local identifier. Conceptually,
it records root checkpoint and frozen-configuration identity, the exact query
artifact, ordered realized memory-transition artifacts, semantic and physical
certificates, the expected lineage-aware descendant state, and the
authoritative cached parent signature. A child becomes a retained seed only
after its state and lineage are certified. Each original checkpoint \(M_i\)
has a frozen Checkpoint Structural
Index
\[
\mathcal{I}(M_i)=(\mathcal{F}_i,\mathcal{Q}_i,\mathcal{P}_i,\mathcal{Z}_i),
\]
where \(\mathcal{F}_i\) contains certified canonical facts,
\(\mathcal{Q}_i\) contains structured query descriptions,
\(\mathcal{P}_i\) is the stable benchmark provenance registry, and
\(\mathcal{Z}_i\) contains structural certificates used for applicability and
validation. A canonical fact has the form
\[
f=(e,r,v,\tau,p),
\]
where \(e\), \(r\), \(v\), and \(\tau\) denote an entity, relation, value, and
temporal scope, and \(p\) is a stable benchmark source identifier. Backend
memory identifiers are adapter-local metadata rather than canonical fact
identities.

The index is query-centered, partial, and certified. Operationally,
\(\operatorname{BuildDescriptor}(q,H_{1:t},Z)\) constructs a search-safe
descriptor \(P(x)\) with a finite set of registered mutation opportunities;
it does not reconstruct every atomic fact or claim global semantic
completeness. Fields may come from benchmark structure,
deterministic or rule-based extraction, or LLM-assisted extraction, but an LLM
judgment alone cannot certify a field. Every field used for applicability must
be checked independently of mutant execution and traceable to stable
provenance. Information that cannot be certified remains unstructured; the
corresponding structured mutation opportunities are inapplicable.

For a structured query, we use
\[
\operatorname{QI}(q)=(e,s_e,r,s_r,\tau,c,\alpha),
\]
where \(s_e\) and \(s_r\) are the entity and relation spans, \(c\) contains
answer-affecting constraints, and \(\alpha\) is checkpoint-relative
answerability. This description contains no gold answer.

Separately, an evaluator-only ReferenceVault stores
\[
G(x)=(a,E^{+},E^{-}),
\]
where \(a\) is the expected answer, \(E^{+}\) is valid supporting evidence,
and \(E^{-}\) is evidence that must not support the current answer. We use
\(a=\bot\) for a checkpoint-relative unsupported query. Gold answers,
\(E^{+}\), \(E^{-}\), correctness annotations, oracle predicates, and failure
verdicts are never exposed to mutation selection, seed retention, scheduling,
or search-value computation. The structural index is non-oracle information;
the scheduler normally receives a frozen obligation projection produced from
it rather than enumerating the full index.

\paragraph{Shared initialization.}
For a fixed benchmark, backend \(b\), and repetition seed \(s\), every method
initializes all eligible checkpoint states under the same frozen protocol.
Each root materialization uses the same frozen artifact and configuration.
Because identical input need not produce identical backend state, \system
compares the observable multiset of
retrievable-entry projections for every checkpoint before method-specific
fuzzing. The exact backend-specific projection is finalized during capability
testing. A condition whose entry-level initialization equivalence cannot be
established is recorded as a capability failure and excluded from paired RQ1
comparison. Equivalent states need not share backend UUIDs or coverage IDs.
The initial admitted assembly over all eligible checkpoints constructs
campaign \(E_0\) once; later
materializations re-bind their physical entries to those existing IDs. Each
campaign then executes the exact original checkpoint/query pairs to create its
own authoritative initial parent observations. Inventory enumeration alone is
not a parent observation. These queries consume no fuzzing budget and
contribute no memory-entry coverage.

\subsection{Mutation}
\label{subsec:mutation}

Given a seed \(x=(M,q)\), \system changes one input at a time. A query mutation
produces \(x'=(M,q')\), whereas a memory-state mutation produces
\(x'=(M',q)\). An operator \(o\) defines a structural applicability condition,
a transformation, a pre-execution validator, and an evaluator-side relation
\(\mathcal{C}_o\). Retained mutants may become seeds in later rounds, but every
individual parent--mutant pair still changes exactly one input.

\paragraph{Query mutations.}
A query mutation keeps \(M\) fixed. We use three classes. A
\emph{meaning-preserving} mutation preserves the requested entity, relation,
temporal scope, answerability, and other answer-affecting constraints. Its
operators paraphrase, shorten removable context, add nonrestrictive context,
or change syntactic form. A \emph{target-changing} mutation changes exactly
one designated primary slot in \(\operatorname{QI}(q)\), chosen from entity,
relation, or temporal scope, while preserving the remaining slots and
constraints. The replacement must have provenance-backed canonical support
for the unchanged request structure. An \emph{unsupported} mutation uses a
structurally well-formed, memory-exclusive session-local replacement derived
deterministically from the checkpoint, query, and opportunity identity.

Unsupportedness requires a checkpoint-relative certificate
\(operatorname{Absent}(z,r,\tau,M)=1\), or the corresponding form without
\(\tau\). The verifier scans the normalized raw checkpoint text and registered
identifiers for the exact synthetic identifier. It never infers absence from
a partial extracted fact table, failed retrieval, a response, or an LLM
assertion. The reserved target is explicitly session-local rather than an
ordinary public-knowledge entity.

\paragraph{Memory-state mutations.}
A memory-state mutation keeps \(q\) fixed and applies a controlled operation
\(\delta\) to an isolated state, producing \(M'=\delta(M)\). \system uses the
backend's native memory operation or interaction semantics and validates the
observable transition before executing the mutant query.

We use three operations. An \emph{update} introduces a later, type-compatible
value for an existing entity--relation pair and remains within that pair's
canonical region. A \emph{deletion} removes or deactivates an existing fact.
It is applicable only if a public or native backend operation faithfully
realizes the designated change. A native cascade is allowed only when its
structural certificate proves that every semantic effect belongs to the
designated deletion.
For Graphiti, episode deletion is applicable only when deleting the episode
satisfies this condition; low-level edge deletion is not used to emulate it.
An \emph{unrelated change} modifies the value or state of an existing
certified semantic entity--relation region that is structurally unrelated to
\(\operatorname{QI}(q)\), has a certifiable semantic state, and maps to a
faithful backend target. It cannot introduce a new region or target a
fallback-only provenance region.

Every physical change caused by a memory operation must be observed and
source-explained, every affected retrieval-returnable object must receive
certified lineage, and no collateral effect may be silent. Native invalidation,
replacement, consolidation, or linked evolution is allowed for Update only
when completely certified and semantically part of the selected update. An
independent semantic change invalidates the mutant. For Unrelated Change, the
complete final semantic difference must stay inside the selected unrelated
region and remain disjoint from
\(\operatorname{RelevantRegions}(\operatorname{QI}(q))\); collateral change
to a relevant region is post-transition semantic drift and invalidates the
mutant.

The ReferenceVault constructs the corresponding \(G(x')\) separately for
offline evaluation. Mutation construction, validation, and scheduling do not
receive that reference.

\paragraph{Mutation obligations and applicability.}
At the beginning of round \(r\), \system freezes the seed corpus
\(\mathcal{S}_r\). A mutation obligation
\(\omega=(x,o,t)\) pairs a seed, an operator, and one concrete structurally
certified target. For backend \(b\), let
\[
\mathcal{T}_{o,b}(x)=
\left\{t:\operatorname{pre}^{\mathrm{struct}}_o(x,t)=1
\land \operatorname{faithful}_b(x,o,t)=1\right\}.
\]
The applicable obligation set is
\begin{equation}
\Omega_{r,b}=
\left\{(x,o,t)\mid x\in\mathcal{S}_r,
t\in\mathcal{T}_{o,b}(x)\right\}.
\label{eq:mutation-obligations}
\end{equation}
It is generated from the frozen structural index rather than manually
pre-written and remains fixed within the round. Random Mutation, Unguided LLM,
LLM-as-Judge, Coverage-Guided, and full \system use the same full-space
backend-specific applicability mask. U-Fuzz-Q and U-Fuzz-M restrict that mask
to query and memory-state mutations, respectively.

The opportunity and its semantic certificate are method-independent. They
record the relation, canonical target, target initialized lineage when
relevant, applicability evidence, generation constraints, and source-backed
possible and semantically acceptable physical transition classes, but no
retrieval feedback or evaluator-only state. Once selected, the exact accepted
RealizedMutationArtifact is persisted
for replay; a generator is never asked to recreate it. Query artifacts retain
the exact mutant query and semantic certificate. Memory artifacts retain the
exact operation payload, target lineage, replacement, temporal values, and
required stable provenance or metadata. Concrete replacement values remain
replay state even though CFS excludes them.

PossibleTransitionOutcomes are source-backed classes the backend operation may
produce; AcceptableTransitionOutcomes are those that could satisfy this
opportunity if fully certified and semantically valid. After execution, the
complete PhysicalTransitionCertificate establishes one
ObservedTransitionOutcome, such as same-ID change, deletion, replacement,
merge, split, or unchanged state. Certification status is separate:
\textsc{unresolved} means lineage could not be established and is not a
physical outcome. An unchanged outcome cannot satisfy an operation requiring
an actual semantic change. An adapter OperationReceipt alone proves neither
the semantic relation nor complete physical lineage.

An opportunity is \textsc{inapplicable} when the operator and target cannot
be used faithfully for the seed and backend. It is excluded from
\(\Omega_{r,b}\), is not generated, and does not enter the applicable
denominator. A candidate is \textsc{invalid} when its obligation was
applicable but the generated result fails validation. Its obligation remains
uncovered and may be retried under a fixed generation-attempt cap. The cap is
selected after the pilot and frozen before full evaluation.

Let \(\Omega_{r,b}^{\mathrm{exec}}\) contain obligations that have produced at
least one valid executed mutant. Diagnostic obligation coverage is
\begin{equation}
\mathrm{Cov}_{\mathrm{mut}}^{(r,b)}=
\frac{|\Omega_{r,b}^{\mathrm{exec}}|}{|\Omega_{r,b}|}.
\label{eq:mutation-coverage}
\end{equation}
Invalid candidates do not cover an obligation.

A completely observed backend transition that violates the certified semantic
relation is also invalid and consumes no budget. When source evidence makes
that semantic drift unavoidable for a target, the opportunity is instead
inapplicable for every method.

\paragraph{Compared search methods.}
Random Mutation selects uniformly among applicable obligations. Unguided LLM
uses an LLM to choose among the same obligations and realize the selected
mutation without retrieval feedback. LLM-as-Judge ranks valid candidates by
their estimated likelihood of exposing a memory-use fault, without evaluator
references, failure labels, oracle verdicts, or retrieval feedback.
Coverage-Guided uses only observed new-memory-entry coverage. Full \system
uses that coverage component together with retrieval-pattern novelty and, for
meaning-preserving mutations, ranked retrieval divergence. The candidate-pool
size and judging cost for LLM-as-Judge are frozen after the pilot.

\paragraph{Validation.}
Every candidate first receives pre-execution semantic validation using its
QueryIntent, structural certificates, and stable provenance. A memory mutation
then receives post-operation certification of its complete physical transition
and semantic postcondition before its public retrieval is executed. Neither
layer uses the mutant retrieval, mutant response, ReferenceVault, or failure
oracle. An LLM may propose a rewrite or contribute a rejection check, but its
judgment alone cannot accept a candidate. Detailed rules appear in
Appendix~\ref{app:mutation-validation}.

\subsection{Execution and Fuzzing}
\label{subsec:execution}

For a seed \(x\), let \(U(x)=(R_k(x),y(x))\) denote the observed ranked
retrieval and final response. Every logical seed stores the authoritative
observation that validly established it together with its exact state and query
identity. For an initial seed, each campaign obtains this observation from its
own retrieval of the exact original checkpoint/query pair after equivalent
initialization. For a descendant, it is the resolved observation that created
the seed. Inventory enumeration is not a parent-query observation, and
rematerialization never replaces the stored signature. For a normal
parent--mutant evaluation, \system reuses cached \(U(x)\) and executes only
\(U(x')\).

A cached parent observation may be reused only when the exact state and query
identity are proven identical. If identity cannot be proven, reconstruction
or a parent execution is logged as overhead rather than silently reused or
silently charged as a mutant probe. The same reconstruction and accounting
protocol is used by all methods.

One campaign is the product of one benchmark corpus, one backend \(b\), one
method \(h\), and one repetition seed \(s\). Its total budget \(B\) counts
valid new mutant executions across the complete eligible seed corpus. One unit
is consumed if and only if semantic validation and exact-parent materialization
succeed, any memory transition and semantic postcondition are completely
certified, the selected public retrieval succeeds, every returned physical
object resolves through frozen campaign lineage, and a valid
ResolvedRetrievalObservation is created. Retrieval feedback and evaluation
occur afterward; evaluator confirmation is not required for \(B\).

Invalid generation, inapplicability, transition uncertainty, semantic drift,
and transient materialization or retrieval failure consume no budget. An
unknown returned object also consumes no budget and triggers the capability
abort protocol rather than being dropped or replaced. Evaluator failure after
a resolved execution does not refund \(B\). Shared initialization,
reconstruction, and separately required parent executions are logged as
overhead.

A child is rematerializable only when an approved protocol can reconstruct its
logical seed and pass \(E_0\) re-binding and descendant-state certification. A
materializable-only child may count as a valid executed leaf but cannot
become a parent unless it is rematerializable under that rule.
Live residency does not satisfy this condition, and every primary method uses
the same admission rule. Sequential query-only siblings may reuse a certified
materialized memory state as an optimization because the selected public APIs
are behaviorally read-only under sequential use; correctness cannot depend on
reuse. Graphiti calls sharing its mutable search recipe are not concurrent
unless later isolated, copied, or serialized.

\paragraph{Failure detection.}
After execution, the evaluator may use \(G(x)\), \(G(x')\), retrieval
provenance, and responses to determine whether the required relation is
violated:
\begin{equation}
F_o(x,x')=
\mathbf{1}\!\left[
\neg\mathcal{C}_o\bigl(U(x),U(x');G(x),G(x')\bigr)
\right].
\label{eq:failure-detection}
\end{equation}
This evaluator runs outside fuzzing search. Its verdict cannot affect seed
retention, scheduling, retries, or search values. The executable definitions
of \(\mathcal{C}_o\), retrieval correctness, and answer matching remain to be
specified before the full evaluation.

We operationalize fault uniqueness using a canonical semantic fault signature
rather than attempting to infer latent implementation root causes. For every
evaluator-confirmed fault, define
\begin{equation}
\operatorname{CFS}(x,x')=(i_0,o_c,\operatorname{QI}_c(q'),t_c,s_f),
\label{eq:cfs}
\end{equation}
where \(i_0\) is the original benchmark checkpoint from which the seed lineage
descends, \(o_c\) is the canonical mutation relation,
\(\operatorname{QI}_c(q')\) is the normalized certified QueryIntent of the
mutant, \(t_c\) is the canonical semantic mutation target, and
\(s_f\in\{\mathrm{R},\mathrm{A},\mathrm{RA}\}\) is the mutually exclusive
retrieval-only, answer/use-only, or combined failure surface. Failure-surface
classification is evaluator-only.

Two failures are identical for UF only when their complete CFS values match.
Within one campaign,
\begin{equation}
\operatorname{UF}@B=
\left|\left\{\operatorname{CFS}(x_t,x'_t):1\leq t\leq B
\land F_{o_t}(x_t,x'_t)=1\right\}\right|.
\label{eq:uf-at-b}
\end{equation}
Deduplication is performed independently in each repetition. Raw witnesses are
retained for every CFS; primary reporting aggregates per-run UF@B values and
does not union signatures across repetitions. Appendix~\ref{app:fault-signature}
specifies operator-specific target normalization and excluded witness fields.
The CFS schema and equality rule over canonicalized values are fixed.
Executable construction of canonical CFS values depends on the separately
frozen normalization procedure and evaluator predicates.

\paragraph{Canonical structural regions.}
For a canonical fact with certified entity and relation, define
\[
\kappa(f)=(\texttt{entity-relation},\operatorname{norm}(e),
\operatorname{norm}(r)).
\]
For source unit \(p\), let \(K_i(p)\) contain the certified semantic keys of
facts whose provenance includes \(p\), and define
\begin{equation}
\operatorname{RegionsForSource}_i(p)=
\begin{cases}
K_i(p), & K_i(p)\neq\varnothing,\\
\{(\texttt{source},p)\}, & K_i(p)=\varnothing.
\end{cases}
\label{eq:source-regions}
\end{equation}
Thus, a source contributes a fallback region only when it yields no certified
entity--relation region. Residual unstructured text does not create a second
region for a source that already has a semantic key.

We distinguish the semantic mutation space from the broader provenance index:
\[
\mathcal{K}^{\mathrm{sem}}_i=\bigcup_{p\in\mathcal{P}_i}K_i(p),
\qquad
\mathcal{K}^{\mathrm{prov}}_i=
\bigcup_{p\in\mathcal{P}_i}\operatorname{RegionsForSource}_i(p).
\]
Only \(\mathcal{K}^{\mathrm{sem}}_i\) contains legal semantic mutation
targets. In particular, Unrelated Change chooses an existing certifiable
backend target from
\(\mathcal{K}^{\mathrm{sem}}_i\setminus
\operatorname{RelevantRegions}(\operatorname{QI}(q))\). A fallback-only
\((\texttt{source},p)\) region remains available for provenance/indexing but
is never an Unrelated Change target.

For a retrieved backend entry \(m\), the adapter first constructs a certified
fact-level mapping
\[
\operatorname{FactMap}_{b,i}(m)=
\{f:m\text{ can reliably be shown to represent }f\},
\]
and defines the semantic region set
\[
R^{\mathrm{sem}}_{b,i}(m)=
\{\kappa(f):f\in\operatorname{FactMap}_{b,i}(m)\}.
\]
The separate conservative fallback set is
\[
R^{\mathrm{fallback}}_{b,i}(m)=
\{(\texttt{source},p):m\text{ has reliable provenance to }p
\land K_i(p)=\varnothing\}.
\]
We then define
\[
\rho_{b,i}(m)=R^{\mathrm{sem}}_{b,i}(m)\cup
R^{\mathrm{fallback}}_{b,i}(m).
\]
When a source has no certified semantic key, reliable source provenance may
map the entry to its source fallback. When it has exactly one semantic key,
reliable source provenance suffices for that key. When it has several keys,
the entry maps only to facts that its content and provenance reliably
identify. An entry that cannot be disambiguated is marked ambiguous or
unmapped rather than assigned every key of its source. A
summarized entry may still map to several regions when it reliably represents
several certified facts. Mutation-generated values inherit their designated
target's key. These definitions support mutation construction, validation,
unrelatedness checks, deletion certification, provenance auditing, and backend
capability analysis. They do not define or qualify \(\mathrm{Cov}@B\).

\paragraph{Retrieval-mapping quality.}
As an internal provenance diagnostic, we may compute
\[
\operatorname{MappingRate}=
\frac{|\{m:\rho_{b,i}(m)\neq\varnothing\}|}
{|\{m:m\text{ is a retrieved entry considered}\}|}.
\]
Mapped, ambiguous, and unmapped counts may also be retained. MappingRate does
not guide scheduling and is not needed to interpret primary memory-entry
coverage.

\paragraph{Initialized memory-entry coverage.}
After entry-level initialization equivalence is established, each method
campaign freezes its own set \(E_0\) of initialized retrievable entries and
assigns opaque local coverage IDs. \(E_0\) is the disjoint union over eligible
checkpoint states: equal content in different checkpoints remains distinct.
Entries have the same object granularity returned by the selected public
retrieval API. Storage enumeration alone is insufficient to admit an object to
\(E_0\).

Every later root materialization atomically re-binds its fresh physical
objects to this existing \(E_0\); it never creates another denominator.
Re-binding permits no new, cross-campaign, or cross-checkpoint ID and must
match complete live-object resolution, expected deletion, stable provenance,
projection and lineage multiplicity, and certified replacement/merge/split
grouping. Projection equality alone cannot disambiguate equal-projection
entries, and enumeration order, generated IDs, UUID sorting, or semantic
similarity cannot be used as a tie breaker. A descendant materialization must
additionally prove observable-state and lineage equivalence, including
deletion state and transition-relevant backend state. Failure is atomic.

A complete PhysicalTransitionCertificate distinguishes the semantic target
from the complete physically affected lineage set and classifies each affected
object as unchanged lineage, same-ID changed, deleted, replaced, a merge or
split participant, newly observed but uncertified, or otherwise unresolved.
Either uncertified classification makes the certificate status unresolved. No
new physical object receives a fresh coverage ID. The lineage registry may
store final merge/split bindings, but the separate certificate proves them.

The reached set starts empty, \(C_0=\varnothing\). For valid fuzzing execution
\(t\), let \(R_t\) be its retrieval and let
\(\operatorname{CoverageIDs}(R_t)\) be the initialized entries represented by
the retrieved physical objects. We update
\begin{equation}
C_t=C_{t-1}\cup\operatorname{CoverageIDs}(R_t),
\qquad
\operatorname{Cov}@B=\frac{|C_B|}{|E_0|}.
\label{eq:entry-coverage}
\end{equation}
Initialization queries and parent observations neither consume \(B\) nor add
to \(C_0\). An in-place or replacement update retains the designated target's
coverage ID; deletion leaves that ID in \(E_0\) without counting the deletion
as retrieval; and an unrelated change remains associated with its selected
initialized target. A split, merge, or replacement that source-backed
capability cannot certify makes that opportunity \textsc{inapplicable}; an
unexpectedly unresolved executed transition is rejected without budget and
handled as a transition/capability failure. Failure to establish \(E_0\) at
retrieval-returnable granularity blocks Cov@B for the condition.
If the complete verified campaign-level inventory is empty, \(|E_0|=0\), the
backend--benchmark condition is RQ1-ineligible: Cov@B is undefined, UF@B is not
reported, and no numeric 0 or 1 is fabricated. An individual empty checkpoint
does not exclude a campaign whose campaign-level \(E_0\) is non-empty.

\paragraph{Canonical retrieval behavior.}
Let the selected public API return
\(R_t=(m_{t,1},\ldots,m_{t,l_t})\), where \(l_t\leq k\). For every
retrieved object, a certified lineage
\(\Gamma_t(m)\subseteq E_0\) identifies the non-empty set of initialized
entries represented by that object. It is normally a singleton, but may contain
multiple entries for a faithfully certified merge. We canonicalize it as one
deterministic token
\(\tau_t(m)=\operatorname{canonical\_tuple}(\Gamma_t(m))\), using one fixed
ordering of campaign-local IDs. Singleton and multi-entry bindings both use
tuples: \(\{e_1\}\) becomes \((e_1)\), while \(\{e_2,e_1\}\) and
\(\{e_1,e_2\}\) both become \((e_1,e_2)\). We then define the ranked behavior
signature
\begin{equation}
\sigma_t=\operatorname{dedup}_{\mathrm{first}}
  (\tau_t(m_{t,1}),\ldots,\tau_t(m_{t,l_t})).
\label{eq:retrieval-signature}
\end{equation}
Duplicate tokens retain only their first occurrence, and an empty retrieval
has signature \(\langle\rangle\). Uncertifiable lineage is a capability
condition rather than grounds to drop an object or substitute raw text,
backend identifiers, FactMap, or canonical regions.
Each complete tuple is one atomic ranked token for signature and RBO
computation. Thus a result grouping \(\{e_1,e_2\}\) followed by one grouping
\(\{e_3\}\) yields \([(e_1,e_2),(e_3)]\), not
\([e_1,e_2,e_3]\). CoverageIDs still unions the underlying entries for
coverage accounting, so atomic grouping affects retrieval behavior rather than
Cov@B.

For each root checkpoint \(i\), \(H_i^{(0)}\) contains the signatures of its
cached initialization observations. These signatures establish prior behavior
but add nothing to \(C_0=\varnothing\) or the Coverage-Guided seen set. A valid
execution is scored against \(H_i^{(t-1)}\), after which
\(H_i^{(t)}=H_i^{(t-1)}\cup\{\sigma_t\}\), whether or not its mutant is
retained. Histories are never compared across checkpoints. Exact new behavior
is
\(\operatorname{NewBehavior}_t=
\mathbf{1}[\sigma_t\notin H_i^{(t-1)}]\) and is logged rather than used as
another scheduler objective.

\paragraph{Novelty and parent-child divergence.}
Using standard extrapolated rank-biased overlap for finite lists, define
\(d_{\mathrm{RBO}}(S,T)=1-\mathrm{RBO}_{\mathrm{EXT},p}(S,T)\in[0,1]\),
where larger values mean more different ranked behavior. Once \(k\) is frozen,
we fix \(p=1-1/k\) and require \(k\geq2\). We set
\(d_{\mathrm{RBO}}(\langle\rangle,\langle\rangle)=0\) and its distance
between one empty and one non-empty list to 1. Retrieval-pattern novelty is
\begin{equation}
N_t=\min_{\sigma\in H_i^{(t-1)}}
d_{\mathrm{RBO}}(\sigma_t,\sigma),
\label{eq:retrieval-novelty}
\end{equation}
with \(N_t=1\) when the prior archive is unexpectedly empty. Only for a
validated Meaning-Preserving Query mutation, the exact cached parent signature
defines
\begin{equation}
D_t=d_{\mathrm{RBO}}(\sigma_{\mathrm{parent}(t)},\sigma_t).
\label{eq:retrieval-divergence}
\end{equation}
No different parent or unverified reconstruction may substitute for it, and
\(D_t\) is not used for the other mutation relations. The signals are distinct:
\(N_t\) measures distance from all previously seen behavior for checkpoint
\(i\), while \(D_t\) measures local instability from the exact parent. A child
can therefore have low novelty because its signature appeared earlier while
remaining highly divergent from its parent.

\paragraph{Coverage and U-Fuzz priorities.}
These priorities are post-execution feedback. Search first selects an eligible
parent and opportunity, realizes and semantically validates the exact artifact,
certifies the parent materialization, certifies any memory transition, executes
the selected public retrieval, and resolves every returned physical object.
Creation of the resulting ResolvedRetrievalObservation consumes one unit of
\(B\). Only then are \(G_t\), \(N_t\), applicable \(D_t\), and either priority
score available. The score controls retention or future expansion priority for
the executed mutant; it cannot rank an unexecuted candidate. The authoritative
cached parent observation supplies parent divergence without changing this
chronology.

Let
\begin{equation}
A_t=\operatorname{CoverageIDs}(R_t),\quad
G_t=|A_t\setminus C_{t-1}|,\quad
C_t=C_{t-1}\cup A_t.
\label{eq:online-entry-gain}
\end{equation}
Coverage-Guided starts with an empty seen set and uses only the raw score
\(S_{\mathrm{CG},t}=G_t\), updating seen with \(A_t\). Certified merged
lineage may make \(G_t>k\), and Coverage-Guided does not clip it.

For U-Fuzz alone, the bounded coverage component is
\begin{equation}
\widetilde{G}_t=\min(1,G_t/k)=\min(G_t,k)/k.
\label{eq:bounded-entry-gain}
\end{equation}
This clipping affects only scheduler priority: every member of \(A_t\) still
enters \(C_t\) and Cov@B. For singleton lineage it reduces to \(G_t/k\); for a
certified merge it saturates without using \(|E_0|\), \(|A_t|\), or another
parameter. Define
\begin{equation}
S_{\mathrm{beh},t}=
\begin{cases}
(N_t+D_t)/2,&\text{Meaning-Preserving Query},\\
N_t,&\text{otherwise},
\end{cases}
\qquad
S_{\mathrm{UF},t}=\frac{\widetilde{G}_t+S_{\mathrm{beh},t}}{2}.
\label{eq:ufuzz-priority}
\end{equation}
Both scores lie in \([0,1]\). This fixed equal-weight scalarization gives
coverage and behavior equal top-level mass without giving meaning-preserving
mutations an extra objective. We reject lexicographic coverage-first selection
because novelty and divergence would matter only on coverage ties, making
U-Fuzz too similar to Coverage-Guided. Pareto selection would require another
choice rule, and outcome-tuned weights would compromise the a priori design.
Coverage-Guided and U-Fuzz use the same repetition-seed-controlled
deterministic principle for exact score ties; queue and eviction mechanics
remain to be fixed.

All quantities in these scores are search-side observations. They use
initialized-entry lineage and ranked retrieval order, never response
correctness, generated-answer behavior, gold answers, ReferenceVault evidence,
CFS failure surfaces, fault verdicts, UF@B, or evaluator predicates. Structural
regions and FactMap remain available for construction and auditing but do not
define any retrieval-feedback score or Cov@B.

Primary results are reported separately for LoCoMo and LongMemEval-S. Each
benchmark--backend--method cell aggregates repetitions over seeds. The
numerical budget, retrieval depth, retry cap, repetition count, uncertainty
statistic, LLM-as-Judge candidate-pool and judging cost, extraction model and
version, entity/relation/time/constraint canonicalization procedure, and
manual-audit sample size are selected after the pilot and frozen before full
evaluation. Backend-specific retrievable-entry projections, concrete queue and
eviction mechanics, and capabilities not yet live-validated are finalized
before execution without changing the definitions above.
