\section{Technical Implementation Details}
\label{app:tech}

\subsection{Checkpoint Structural Index}
\label{app:structural-index}

Before fuzzing a checkpoint \(M_i\), \system builds and freezes
\[
\mathcal{I}(M_i)=(\mathcal{F}_i,\mathcal{Q}_i,
\mathcal{P}_i,\mathcal{Z}_i).
\]
The provenance registry \(\mathcal{P}_i\) contains every stable benchmark
source unit used to construct the checkpoint. A canonical fact in
\(\mathcal{F}_i\) has the form
\[
f=(e,r,v,\tau,p),
\]
where \(p\in\mathcal{P}_i\). The index records the source support and
certification checks for each structured field. Backend-generated identifiers
are stored only in adapter-local mappings and never replace \(p\).

\paragraph{Partial-but-certified extraction.}
Structured fields may come from benchmark schemas, deterministic parsing,
rules, or LLM-assisted extraction. An LLM assertion alone is not a
certificate. Before a field is used for mutation applicability, \system
checks the corresponding benchmark source, span, type, relation support, or
temporal order independently of mutant execution. A field that cannot be
certified remains unstructured. The index may therefore be incomplete without
fabricating metadata.

For a query that admits structured mutation, \(\mathcal{Q}_i\) stores
\[
\operatorname{QI}(q)=(e,s_e,r,s_r,\tau,c,\alpha),
\]
where the spans \(s_e,s_r\) locate the requested entity and relation, \(c\)
stores answer-affecting constraints, and \(\alpha\) records
checkpoint-relative answerability. QueryIntent does not store the expected
answer.

\paragraph{Checkpoint-relative absence.}
An unsupported opportunity requires a certificate
\[
\operatorname{Absent}(z,r,\tau,M_i)=1,
\]
or the corresponding form without \(\tau\). The verification procedure
examines the full checkpoint provenance relevant to the requested entity,
relation, and temporal scope. It does not infer absence merely because no
matching tuple appears in the partial \(\mathcal{F}_i\). The verifier may
combine deterministic matching, structured lookup, and LLM-assisted analysis,
but an LLM assertion alone cannot establish absence. The certificate is fixed
before execution and means only that the request is unsupported by the current
checkpoint.

\paragraph{Structural and evaluator information.}
The structural index contains non-oracle information required for mutation
applicability and canonical region mapping. The preferred flow is
\[
\mathcal{I}(M_i)\longrightarrow
\text{obligation builder}\longrightarrow
\Omega_{r,b}\longrightarrow
\text{scheduler}.
\]
The scheduler normally consumes a frozen projection of
\(\Omega_{r,b}\); this interface choice is not a claim that the structural
index is evaluator-sensitive. The separate ReferenceVault stores gold answers,
\(E^{+}\), \(E^{-}\), correctness annotations, evaluator predicates, and
failure verdicts. Those values are unavailable to mutation construction and
search.

\subsection{Mutation Implementation}
\label{app:mutation-implementation}

Given \(x=(M,q)\) and applicable obligation \(\omega=(x,o,t)\), \system
constructs a candidate according to an operator and target drawn from the
frozen applicable obligation space. The compared method determines how an
obligation is selected or prioritized. Once an obligation is fixed, an LLM may
realize a query operation in free form but cannot change its certified target
or memory-state transition. Unguided LLM may use an LLM to choose among the
same applicable obligations, but it receives no retrieval feedback and cannot
leave that space.

\subsubsection{Meaning-Preserving Query Mutation}

Meaning-preserving operations change the surface form while preserving the
entity, relation, temporal scope, answerability, and answer-affecting
constraints in \(\operatorname{QI}(q)\). We use four transformations:
paraphrasing, shortening removable context, adding nonrestrictive context, and
changing syntactic form.

For paraphrasing, the fixed QueryIntent fields are protected while an LLM
expresses the request in different wording. For shortening, \system removes a
known removable span directly or asks an LLM for a shorter realization while
protecting the fixed fields. Nonrestrictive context is accepted only when it
introduces no new constraint. Syntactic-form changes use deterministic
templates when possible and otherwise use an LLM only for grammatical
realization.

\subsubsection{Target-Changing Query Mutation}

A target-changing operation designates one primary field
\(z\in\{e,r,\tau\}\) and a fixed replacement \(z'\). The replacement must be
type-compatible and backed by a certified canonical fact for the unchanged
request structure. The other primary fields and constraints remain fixed.

When the target has a replaceable span, \system applies
\[
q'=q[z\leftarrow z'].
\]
Otherwise, an LLM receives the original QueryIntent and the fixed replacement
only to produce a grammatical form. The scheduler-facing obligation does not
contain the evaluator's expected answer for the replacement. The ReferenceVault
constructs \(G(x')\) separately.

\subsubsection{Unsupported Query Mutation}

An unsupported mutation uses a type-compatible, structurally well-formed
replacement for which
\(operatorname{Absent}(z',r,\tau,M_i)=1\). The target and certificate are
fixed before query realization. Direct slot replacement is used when possible;
otherwise, an LLM may express the already fixed target grammatically.

Neither absence from the partial fact table, failed retrieval, an incorrect
answer, nor an uncorroborated LLM claim establishes unsupportedness. The
evaluator separately assigns the resulting checkpoint-relative reference with
\(a'=\bot\).

\subsubsection{Update Memory Mutation}

An update starts from a certified fact
\[
(e,r,v_{\mathrm{old}},\tau,p)
\]
and fixes a different, type-compatible value \(v_{\mathrm{new}}\) under a
later temporal or state position. The intended transition preserves \(e\) and
\(r\):
\[
(e,r,v_{\mathrm{old}})\longrightarrow(e,r,v_{\mathrm{new}}).
\]
Both values belong to the same canonical structural region. If the designated
backend target is an initialized coverage entry, an in-place update retains its
coverage ID and a certified replacement or later record inherits that ID.

If the backend exposes a public update operation, \system invokes it. If the
backend represents updates through later interactions or episodes, \system
appends the fixed later interaction and lets the backend process it normally.
It does not directly rewrite backend state into a desired final state. A
backend may retain the old value as history; validity depends on whether its
observable state represents the new value according to its native semantics.

\subsubsection{Deletion Memory Mutation}

A deletion targets an existing certified fact and a faithful public or native
backend operation. Its obligation is applicable only if that operation can
realize the designated transition without changing other information relevant
to the fixed query or otherwise violating the one-input mutation relation.

The adapter may use a backend-local identifier to invoke the operation, but it
must first resolve that identifier to stable checkpoint provenance. Low-level
storage operations are not used to imitate a semantic deletion that the
backend does not support. In particular, Graphiti episode deletion is
applicable only when deleting the episode does not remove multiple relevant
facts or otherwise violate the intended transition; low-level edge deletion is
not substituted. An unsupported deletion opportunity is marked
\textsc{inapplicable}.

Deletion may make the target inactive in the descendant state. Its canonical
structural region remains available for validation, and its initialized
coverage entry remains in the frozen denominator \(E_0\). Deletion itself does
not count as retrieval.

\subsubsection{Unrelated Change Memory Mutation}

An unrelated change selects an already indexed structural region
\[
u\in \mathcal{K}_i\setminus
\operatorname{RelevantRegions}(\operatorname{QI}(q)).
\]
It changes the value or state within \(u\) using the backend's normal
operation. All indexed information structurally relevant to the fixed
QueryIntent must remain unchanged. For example, a query about Alice's
residence may be paired with a change from Bob's hobby of tennis to golf when
Bob's hobby is already an indexed region.

The operator cannot introduce a wholly new entity--relation region or coverage
target. A proposed change outside \(\mathcal{K}_i\), or one whose resulting
physical entry cannot be certified as the selected initialized coverage target,
is \textsc{inapplicable}. Unrelatedness is established from QueryIntent and
structural regions, not from \(E^{+}\) or \(E^{-}\).

\subsection{Mutation Applicability and Validation}
\label{app:mutation-validation}

For backend \(b\), an opportunity enters
\(\mathcal{T}_{o,b}(x)\) only if its structural precondition holds and the
backend can faithfully realize it. The resulting full-space applicability mask
is frozen and shared by Random Mutation, Unguided LLM, LLM-as-Judge,
Coverage-Guided, and full \system for the same benchmark, backend, and
repetition condition. U-Fuzz-Q and U-Fuzz-M use its query-only and memory-only
restrictions. Exclusion reasons are recorded.

\textsc{Inapplicable} describes an operator-target pair that cannot be
faithfully constructed or executed. Such a target is excluded from
\(\Omega_{r,b}\), is not sent to a generator, and does not enter the applicable
obligation denominator. \textsc{Invalid} describes a generated candidate for
an applicable obligation that fails validation. Invalid generation does not
consume the valid-execution budget, leaves the obligation uncovered, and may
be retried under the cap frozen after the pilot.

For candidate \(x'\) generated from \(x\) by \(o\), validation produces
\[
V_o(x,x')\in\{0,1\}.
\]
Execution occurs only if \(V_o(x,x')=1\). The certificate uses the parent and
candidate forms, structural index, provenance, and observable backend
operation or state information. It never uses the mutant retrieval, mutant
response, ReferenceVault, or failure oracle. An LLM may generate a candidate
or contribute a rejection check, but cannot make the final acceptance decision
alone.

\paragraph{Query validation.}
A meaning-preserving candidate is valid only when its certified QueryIntent
preserves \(e,r,\tau,c,\alpha\). A target-changing candidate is valid only
when the designated slot has the fixed replacement and the remaining primary
slots and constraints are unchanged. Unsupported validation additionally
requires the precomputed checkpoint-wide absence certificate.

\paragraph{Memory-state validation.}
Memory validation checks \(M\rightarrow M'\) independently of query behavior.
An update must preserve entity and relation, use the fixed new value at a later
state position, remain in the target's structural region and initialized
coverage target, and be observably represented under native backend semantics.
A deletion must show that the designated target existed before the operation
and became removed or inactive afterward with no unintended relevant change.
An unrelated change must remain within its fixed existing structural region
and initialized coverage target, and leave all structurally relevant indexed
information unchanged. If a split, merge, or replacement cannot be certified
to the designated initialized target, that opportunity is
\textsc{inapplicable}.

When the backend cannot provide operation results or observable state
sufficient for these checks, the opportunity is \textsc{inapplicable} for
RQ1. It is not admitted as an unverified behavioral probe.

\subsection{Canonical Structural Regions and Provenance Mapping}
\label{app:region-mapping}

For a certified fact, define
\[
\kappa(f)=(\texttt{entity-relation},
\operatorname{norm}(e),\operatorname{norm}(r)).
\]
The normalization procedure is chosen after the pilot and frozen before full
evaluation. It is shared across methods.

For every stable checkpoint source unit \(p\), let
\[
K_i(p)=\{\kappa(f):f\text{ has provenance }p
\text{ and a certified entity--relation key}\}.
\]
The source contributes
\[
\operatorname{RegionsForSource}_i(p)=
\begin{cases}
K_i(p), & K_i(p)\neq\varnothing,\\
\{(\texttt{source},p)\}, & K_i(p)=\varnothing.
\end{cases}
\]
Thus, a source with any certified semantic key contributes only its certified
semantic regions. Partial residual text does not cause a simultaneous source
fallback. When the source yields no certified entity--relation region, the
stable source ID is the sole conservative fallback.

The checkpoint's certified structural key set is
\[
\mathcal{K}_i=
\bigcup_{p\in\mathcal{P}_i}\operatorname{RegionsForSource}_i(p).
\]
This set supports structural reasoning and is not the Cov@B denominator. For
every retrieved entry \(m\), the backend adapter resolves local identifiers to
stable provenance and constructs
\[
\operatorname{FactMap}_{b,i}(m)=
\{f:m\text{ can reliably be shown to represent }f\}.
\]
It then defines
\[
R^{\mathrm{sem}}_{b,i}(m)=
\{\kappa(f):f\in\operatorname{FactMap}_{b,i}(m)\}.
\]
Source fallback is represented separately:
\[
R^{\mathrm{fallback}}_{b,i}(m)=
\{(\texttt{source},p):m\text{ has reliable provenance to }p
\land K_i(p)=\varnothing\}.
\]
The complete mapping is
\[
\rho_{b,i}(m)=R^{\mathrm{sem}}_{b,i}(m)\cup
R^{\mathrm{fallback}}_{b,i}(m)\subseteq \mathcal{K}_i.
\]
If source \(p\) has no certified semantic region, reliable provenance to
\(p\) may map \(m\) to \((\texttt{source},p)\). If \(p\) has exactly one
certified semantic region, reliable provenance to \(p\) is sufficient for
that mapping. If \(p\) has multiple semantic regions, \(m\) maps only to the
subset of canonical facts that its content and provenance reliably identify.
When such an entry cannot be disambiguated, the adapter marks it ambiguous or
unmapped instead of assigning all of \(K_i(p)\). A summarized
entry may map to several regions only when it reliably represents several
certified facts. Values created by a valid memory mutation inherit the
canonical key of their designated indexed target. If reliable checkpoint
provenance is absent, the adapter records the entry as unmapped and does not
invent a region. These mappings support mutation construction and validation,
unrelatedness checks, deletion certification, provenance auditing, and backend
capability analysis. They do not define or qualify Cov@B.

\paragraph{Mapping-quality diagnostic.}
For retrieved entries considered during provenance auditing, we may compute
\[
\operatorname{MappingRate}=
\frac{|\{m:\rho_{b,i}(m)\neq\varnothing\}|}
{|\{m:m\text{ is a retrieved entry considered}\}|}.
\]
We may also log mapped, ambiguous, and unmapped fact/provenance mappings.
MappingRate is an internal quality diagnostic only: it does not guide
scheduling, seed retention, or mutation selection, and it is not required to
interpret primary memory-entry coverage.

\subsection{Initialized Memory-Entry Coverage}
\label{app:entry-coverage}

For one method campaign, let \(E_0\) be the disjoint union of retrievable
entries frozen from all eligible checkpoint states after initialization
equivalence is established. Each entry is checkpoint-local and receives an
opaque campaign-local ID. Similar content in different checkpoints remains
distinct, and no cross-method coverage-ID correspondence is required.

An entry is admitted to \(E_0\) only at the backend object granularity returned
by the selected public retrieval API: a Mem0 memory record, A-Mem note, or
Graphiti fact/edge object. Storage enumeration by itself is insufficient. The
capability test must verify that the inventory corresponds to the retrieval-
returnable object class. Failure to establish this inventory blocks Cov@B for
that backend/benchmark condition.
If the complete verified campaign-level inventory is empty, \(|E_0|=0\), the
backend--benchmark condition is RQ1-ineligible. Cov@B is undefined, UF@B is not
reported, and no numeric 0 or 1 is fabricated. The condition is recorded as a
capability/ineligibility result. An individual checkpoint with no retrievable
entry does not exclude a campaign whose campaign-level \(E_0\) is non-empty.

Coverage starts with \(C_0=\varnothing\). For the retrieval \(R_t\) of valid
fuzzing execution \(t\), the adapter resolves physical entries to initialized
coverage IDs and updates
\[
C_t=C_{t-1}\cup\operatorname{CoverageIDs}(R_t).
\]
After \(B\) valid executions,
\[
\operatorname{Cov}@B=\frac{|C_B|}{|E_0|}.
\]
Initialization queries and parent observations do not enter \(C_0\). An
in-place update retains the target ID; a certified replacement or later record
inherits it; deletion leaves the ID in \(E_0\) without itself counting as
retrieval; and Unrelated Change stays associated with its selected initialized
target. An uncertifiable split, merge, or replacement makes that mutation
opportunity \textsc{inapplicable} rather than excluding the entire condition.

\subsection{Retrieval Feedback}
\label{app:retrieval-feedback}

For valid fuzzing execution \(t\), the selected public API returns
\[
R_t=(m_{t,1},\ldots,m_{t,l_t}),\qquad l_t\leq k.
\]
The lineage resolver must certify a non-empty
\(\Gamma_t(m)\subseteq E_0\) for every returned physical object. Ordinarily
this set is a singleton. If the backend faithfully merges initialized entries,
it may contain more than one ID. We encode the binding as the deterministic
token
\[
\tau_t(m)=\operatorname{canonical\_tuple}(\Gamma_t(m)),
\]
using one fixed deterministic ordering of campaign-local IDs. Every binding
uses the same tuple type: \(\{e_1\}\) becomes \((e_1)\), while
\(\{e_2,e_1\}\) and \(\{e_1,e_2\}\) both become \((e_1,e_2)\). The ranked
signature is
\[
\sigma_t=\operatorname{dedup}_{\mathrm{first}}
(\tau_t(m_{t,1}),\ldots,\tau_t(m_{t,l_t})),
\]
where only the first occurrence of an identical token is retained. The empty
retrieval has signature \(\langle\rangle\). If any required lineage cannot be
certified, the adapter reports an unresolved lineage or capability condition;
it cannot discard the object, invent a token, or substitute backend UUIDs, raw
text, scores, embeddings, FactMap, or canonical structural regions.
The complete tuple is one atomic ranked token for signature and RBO
computation; constituent IDs are not expanded into artificial positions. For
example, physical results representing \(\{e_1,e_2\}\) and then \(\{e_3\}\)
produce \([(e_1,e_2),(e_3)]\), not \([e_1,e_2,e_3]\). The latter expansion
would erase the public API's object grouping. CoverageIDs separately unions all
underlying IDs, so both groupings reach \(\{e_1,e_2,e_3\}\) for \(G_t\),
\(C_t\), and Cov@B. Signatures \([(e_1,e_2),(e_3)]\) and
\([(e_1),(e_2),(e_3)]\) are therefore behaviorally distinct. First-occurrence
deduplication removes only identical complete tuple tokens.

Each root checkpoint \(i\) has an independent archive \(H_i\). Cached original
parent and baseline observations initialize
\[
H_i^{(0)}=\{\text{canonical signatures observed during initialization for }i\}.
\]
They seed only this behavior archive, not \(C_0\) or the Coverage-Guided seen
set. A valid execution descended from \(i\) is scored against
\(H_i^{(t-1)}\) before
\[
H_i^{(t)}=H_i^{(t-1)}\cup\{\sigma_t\},
\]
and insertion occurs even if the mutant is not retained. Other checkpoints'
archives are unchanged. We log
\[
\operatorname{NewBehavior}_t=
\mathbf{1}[\sigma_t\notin H_i^{(t-1)}]
\]
for analysis, but do not add it as a scheduler objective.

Let \(\mathrm{RBO}_{\mathrm{EXT},p}\) be standard extrapolated RBO for finite
ranked lists and set
\[
d_{\mathrm{RBO}}(S,T)=1-\mathrm{RBO}_{\mathrm{EXT},p}(S,T),
\qquad p=1-1/k,
\]
where \(d_{\mathrm{RBO}}\in[0,1]\), larger values mean more different ranked
behavior, and the primary experiment requires \(k\geq2\). The persistence is
therefore fixed by retrieval depth and is not tuned on UF@B or Cov@B. Empty
lists obey
\[
d_{\mathrm{RBO}}(\langle\rangle,\langle\rangle)=0,
\qquad
d_{\mathrm{RBO}}(\langle\rangle,T)
=d_{\mathrm{RBO}}(T,\langle\rangle)=1
\]
for non-empty \(T\). Checkpoint-local novelty is
\[
N_t=\min_{\sigma\in H_i^{(t-1)}}d_{\mathrm{RBO}}(\sigma_t,\sigma)
=1-\max_{\sigma\in H_i^{(t-1)}}
\mathrm{RBO}_{\mathrm{EXT},p}(\sigma_t,\sigma).
\]
If the prior archive is empty despite initialization, \(N_t=1\) and the
condition is logged.

For a validated Meaning-Preserving Query mutation only, let
\(\sigma_{\mathrm{parent}(t)}\) come from the exact cached parent observation
and define
\[
D_t=d_{\mathrm{RBO}}(\sigma_{\mathrm{parent}(t)},\sigma_t).
\]
An observation from another parent, an unverified reconstruction, or a similar
query cannot substitute. If exact parent identity is unavailable, \(D_t\) is
unavailable. We do not use \(D_t\) for Target-Changing Query, Unsupported
Query, Update, Deletion, or Unrelated Change. Novelty is global within the
checkpoint archive, whereas divergence is local to the exact parent: a child
signature seen earlier can have \(N_t\approx0\) and still have
\(D_t\approx1\) relative to its parent.

For online memory-entry gain, let
\[
A_t=\operatorname{CoverageIDs}(R_t),\qquad
G_t=|A_t\setminus C_{t-1}|,
\qquad C_t=C_{t-1}\cup A_t.
\]
All initialized entries in certified multi-entry bindings enter \(A_t\) and
\(C_t\). Consequently \(G_t\) may exceed \(k\). Coverage-Guided starts with
\(\mathrm{seen}=\varnothing\), uses only
\[
S_{\mathrm{CG},t}=G_t,
\qquad \mathrm{seen}\leftarrow\mathrm{seen}\cup A_t,
\]
and does not clip this score. Initialization retrievals receive no coverage
credit.

These are post-execution feedback scores. The implementation selects an
eligible parent and opportunity, generates and validates the mutant, executes
the valid mutant, and observes \(R_t\) before computing \(G_t\), \(N_t\),
applicable \(D_t\), and \(S_{\mathrm{CG},t}\) or \(S_{\mathrm{UF},t}\). The
execution has already consumed one unit of \(B\). Its score affects retention
or future expansion priority for that executed mutant and cannot rank an
unexecuted candidate. Parent divergence continues to use the exact cached
parent observation.

Only the U-Fuzz scalarization uses the clipped component
\[
\widetilde{G}_t=\min(1,G_t/k)=\frac{\min(G_t,k)}{k}.
\]
It equals \(G_t/k\) under singleton lineage and saturates at 1 when certified
merges make \(G_t>k\). Clipping does not alter \(A_t\), \(G_t\), \(C_t\),
Cov@B, or Coverage-Guided. It uses neither \(|E_0|\) nor \(|A_t|\) as a
denominator and introduces no additional parameter.

The behavior and final scores are
\[
S_{\mathrm{beh},t}=
\begin{cases}
(N_t+D_t)/2,&\text{validated Meaning-Preserving Query},\\
N_t,&\text{otherwise},
\end{cases}
\qquad
S_{\mathrm{UF},t}=\frac{\widetilde{G}_t+S_{\mathrm{beh},t}}{2}.
\]
Both are bounded by 1. The equal top-level weights are fixed a priori. A
lexicographic coverage-first rule would make behavior feedback matter only on
ties and collapse U-Fuzz toward Coverage-Guided; Pareto ranking would still
require another action-selection rule; and outcome-tuned weights would leak
experimental optimization into the method. Both scored methods resolve exact
ties using the same deterministic repetition-seed-controlled principle. Queue
capacity, eviction, and batching policies remain implementation parameters.

All lineage, signatures, histories, and scores in this subsection are search-
side. They cannot use generated-answer correctness, gold answers,
ReferenceVault data, CFS failure surfaces, R/A/RA labels, fault verdicts, UF@B,
or evaluator predicates. Canonical structural regions and fact/provenance
mappings retain their construction, validation, audit, and capability roles
but do not define these scores or Cov@B.

\subsection{Canonical Semantic Fault Signature}
\label{app:fault-signature}

We operationalize fault uniqueness through a canonical semantic fault
signature, not by inferring latent software root causes. For an evaluator-
confirmed failing execution,
\[
\operatorname{CFS}=
(i_0,o_c,\operatorname{QI}_c(q'),t_c,s_f).
\]
Here, \(i_0\) is the original benchmark checkpoint from which the seed lineage
descends. Descendant state IDs, replay IDs, backend UUIDs, and execution numbers
cannot replace \(i_0\). The canonical relation \(o_c\) is one of Meaning-
Preserving Query, Target-Changing Query, Unsupported Query, Update, Deletion,
or Unrelated Change. Paraphrasing, shortening, nonrestrictive-context addition,
and syntactic-form change all normalize to Meaning-Preserving Query.

The canonical mutant intent \(\operatorname{QI}_c(q')\) contains normalized,
certified entity, relation or attribute, temporal scope, answer-affecting
constraints, and checkpoint-relative answerability. It never contains raw
query wording. The canonical target \(t_c\) is normalized by relation:
\begin{itemize}
    \item Meaning-Preserving Query uses the empty target.
    \item Target-Changing Query uses the designated changed slot and canonical
    replacement target.
    \item Unsupported Query uses the designated changed slot or canonically
    represented unsupported target; the mutant intent is checkpoint-relative
    unanswerable.
    \item Update uses the canonical entity--relation target and temporal scope
    when structurally relevant. The replacement value is excluded.
    \item Deletion uses the canonical semantic deletion target needed to
    distinguish propositions, including entity, relation or attribute, value,
    and temporally relevant scope. Stable provenance, duplicate source copies,
    and backend physical IDs remain in witness or audit records but do not
    distinguish the UF signature when they represent the same semantic target.
    \item Unrelated Change uses the canonical unrelated entity--relation target
    and temporal scope when structurally relevant. The replacement value is
    excluded.
\end{itemize}

The failure surface \(s_f\) is exactly one of \(\mathrm{R}\) for retrieval-
side failure only, \(\mathrm{A}\) for answer/use-side failure only, or
\(\mathrm{RA}\) for both. The executable predicates for retrieval correctness,
\(\mathcal{C}_o\), and \(\operatorname{Ans}\) remain to be frozen in the
evaluator specification. Surface classification and the resulting confirmed
fault verdict are evaluator-only and are unavailable to search.

The CFS excludes raw query and paraphrase text, exact generated response,
backend and retrieval-entry UUIDs, exact retrieval-rank perturbation, concrete
Update and Unrelated Change replacement values, random seed, execution index,
scheduling path, descendant state ID, repetition ID, and method name. These
fields remain available in raw witness records. Every CFS retains all
associated confirmed failing executions, but UF@B counts the signature once.
Consequently, meaning-preserving paraphrases with the same remaining fields
collapse, as do updates of Alice's residence to Seattle versus Chicago when
their remaining fields match. The same semantic test classified as
\(\mathrm{R}\) versus \(\mathrm{A}\) remains distinct because its failure
surface differs; deletions of genuinely different canonical facts also remain
distinct.

Two confirmed failures are identical if and only if their complete CFS values
are identical. For one campaign,
\[
\operatorname{UF}@B=
\left|\left\{\operatorname{CFS}(x_t,x'_t):1\leq t\leq B
\land F_{o_t}(x_t,x'_t)=1\right\}\right|.
\]
Deduplication is independent within each repetition. Primary reporting
aggregates per-run UF@B values and never substitutes the size of a cross-
repetition union. Such a union may be reported only as a secondary corpus-
discovery diagnostic. “Unique fault” therefore means unique under this declared
CFS equivalence relation.

The CFS field schema, operator-specific target semantics, excluded fields,
equality rule over canonicalized values, per-repetition deduplication, and
witness retention are fixed. Executable construction of canonical CFS values
depends on the separately frozen entity/relation/time/constraint normalization
procedure and evaluator predicates, which must be fixed before RQ1 execution.

\subsection{Campaign Initialization and Execution Accounting}
\label{app:campaign-accounting}

One campaign is identified by
\[
(d,b,h,s),
\]
for benchmark corpus \(d\), backend \(b\), method \(h\), and repetition seed
\(s\). Its total budget \(B\) is the number of valid new mutant executions
across the complete eligible seed corpus.

For fixed \((d,b,s)\), every method constructs all eligible checkpoint states
under the same frozen initialization protocol. Exact cloning is preferred. If
cloning is unavailable, methods replay the same artifacts with all controllable
randomness, model versions, prompts, decoding settings, and ingestion
configuration frozen. Before method-specific fuzzing, \system compares the
observable multiset of retrievable-entry projections for each checkpoint. The
backend-specific projection is finalized during capability testing. If entry-
level equivalence cannot be established, the condition is recorded as a
capability failure and excluded from paired comparison. Backend UUID equality
and cross-method coverage-ID equality are not required.

After equivalence is established, each method freezes its own \(E_0\), assigns
opaque local coverage IDs, and starts with \(C_0=\varnothing\). The original
query set is executed to produce parent observations. These executions consume
no units of \(B\), add no entries to \(C_0\), and do not populate the
Coverage-Guided seen set. Their canonical retrieval signatures do initialize
the checkpoint-local behavior archives \(H_i^{(0)}\).

An observation cache is keyed by exact state identity and exact query
identity. An initial seed receives its cached \(U(x)\) during shared
initialization. When a valid mutant is executed, its \(U(x')\) is stored with
the retained seed. If that exact seed later becomes a parent, the stored
observation is reused, and only the new mutant execution consumes one unit of
\(B\).

State and query identity must be proven before reuse. If a backend state must
be reconstructed or identity cannot be established, \system logs the replay,
reconstruction, or parent execution separately. Such overhead is neither
silently reused nor silently counted as a valid mutant probe. The same identity
and overhead protocol is used by all methods.

Each campaign stops after exactly \(B\) valid new mutant executions. Invalid
generation and inapplicable opportunities consume no units. Initialization and
reconstruction overhead is reported separately.

Primary results do not pool LoCoMo and LongMemEval-S. Each benchmark--backend--
method cell aggregates repeated campaigns over repetition seeds. The number of
repetitions and uncertainty statistic are frozen after the pilot.

\subsection{Manual Audit and Information-Flow Check}
\label{app:audit-information-flow}

After the automatic pipeline operates, we conduct a stratified manual audit
across benchmark, mutation operator, and backend where backend semantics affect
applicability. The audit covers QueryIntent and span extraction, canonical
facts, provenance mapping, target-changing validity, checkpoint-relative
absence, fact-level retrieval-to-region mapping accuracy, update relations,
deletion applicability, and unrelated-change validity. We report the sampling
procedure, sample counts, exclusion reasons, and empirical metadata and
mutation validity rates. We additionally report retrieval-mapping accuracy,
MappingRate, and mapped, ambiguous, and unmapped fact/provenance mappings only
as internal quality diagnostics. They do not define or qualify Cov@B. The
sample size is chosen after the pilot and frozen before full evaluation; the
audit is quality control rather than the primary construction mechanism.

We also test the search/evaluator boundary. Given a sealed observable
execution trace, we permute evaluator-only gold answers and failure labels and
replay scheduling and retention from the same retrieval observations. Every
scheduling and retention decision must remain identical. The executable
definitions of \(\mathcal{C}_o\), retrieval correctness, and answer matching
are specified separately before full evaluation rather than inferred by the
implementation.
